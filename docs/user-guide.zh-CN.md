# MindPet 安装与使用指南

适用版本 1.2.0 · Windows x64 · 2026 年 10 月 16 日

本指南面向首次安装的普通用户。按顺序完成安装、对话模型和记忆向量配置，即可开始使用。MindPet 的核心能力是跨会话的长期记忆，并可按任务调用本地文件、办公和桌面操作工具。

## 1 安装与首次启动

### 需要准备什么

| 项目 | 说明 |
| --- | --- |
| 电脑 | Windows 10 或 11，64 位；安装包为 Windows x64 版本 |
| 安装文件 | mindpet-1.2.0-setup.exe |
| 对话模型 | 可用的模型 API Key、模型名；自定义平台还需要 Base URL |
| 记忆向量 | 使用云端时，准备豆包方舟 Embedding API Key 与对应模型权限 |
| 网络 | 能访问所选模型平台；API 调用费用由模型平台收取 |

安装包内置 Java 后端与运行时，无需另行安装 JDK、Maven、Node.js 或数据库。选择云端对话和云端 Embedding 时，无需安装 Ollama。

### 安装步骤

1. 从项目 GitHub Releases 或随附目录取得安装包，双击运行。
2. 按安装向导选择安装目录并完成安装，通过桌面快捷方式启动 MindPet。
3. 首次启动等待本地服务就绪，再打开主界面的“设置”。
4. 在“后端连接”中保留默认地址 http://127.0.0.1:8080，点击“测试连接”。普通安装用户无需填写公网服务器地址。
5. 进入“模型配置”，依次完成第 2、3 节的设置。对话模型与记忆向量是两项独立服务，应分别确认状态。

如果 Windows 显示安全提示，先核对下载来源、文件名与本目录的 SHA256SUMS.txt，再根据系统提示决定是否安装。不要使用来源不明的安装包。

**最快的云端配置路径：** 安装启动 → 后端连接可达 → 配置 LLM 并测试 → Embedding 选择“强制云端”并检测 → 发送一条普通聊天消息。

## 2 配置对话模型

打开“设置 → 模型配置”。对话模型负责回答问题、理解任务和决定何时调用工具。

| 界面字段 | 如何填写 |
| --- | --- |
| API 服务商 | 选择 Key 所属的平台；兼容 OpenAI 接口的平台可选 CUSTOM |
| Base URL | 填模型平台提供的 API 基准地址，不是官网地址，也不是普通聊天网页地址 |
| 模型名称 | 填当前账号有权调用的准确模型 ID，不要把页面展示名称当作接口 ID |
| 对话模型 API Key | 粘贴该平台签发的 API 密钥，再点击“安全保存” |
| Temperature | 初次使用可保留默认值；是否支持该参数取决于模型 |

### 推荐的填写顺序

1. 先选择服务商；使用自定义平台时，先填写 Base URL，点击输入框外部完成保存。
2. 填写模型名称，可使用模型列表选择；列表加载失败时，也可按平台控制台提供的 ID 手动填写。
3. 最后粘贴 API Key，点击“安全保存”。等待显示已保存并同步至本地服务。
4. 点击“测试大模型连接”，确认检测通过，再返回聊天页面发送一条简短消息，验证真实聊天链路。

更换服务商或 Base URL 后，需要重新填写该服务的密钥。为防止旧 Key 被发送给新地址，程序会清除原有凭证关联；因此应先确定服务地址，再保存 Key。

### DeepSeek 填写示例

- 服务商：DEEPSEEK。
- Base URL：https://api.deepseek.com/v1。
- 模型名称：以 DeepSeek 控制台当前支持且账号可用的模型 ID 为准；应用提供 deepseek-chat 作为预填示例。
- API Key：你自己在该平台创建的密钥，本指南不提供公共 Key。

豆包等平台可能要求填写模型或推理接入点 ID，应使用自己账号下的有效 ID。界面预填值不代表你的账号拥有对应权限。普通聊天产品的会员订阅不能直接替代 API 凭证。

“已安全保存”表示凭证已保存在本机，“已同步”表示 Java 服务已收到配置，“测试通过”表示一次真实模型请求成功。三者含义不同；测试通过后，仍建议发送普通聊天验证流式响应。

## 3 配置长期记忆的向量服务

Embedding 将文本转换为向量，供长期记忆的向量写入与检索使用。LLM 可用不代表 Embedding 可用；未配置向量服务时，基础对话仍可独立使用，但长期记忆的向量能力会受影响。

### 不安装 Ollama 的云端方案

1. 在豆包方舟平台准备可调用 Embedding 模型的 API Key，并确认模型权限、额度与网络可用。
2. 进入“设置 → 模型配置”，找到下方的记忆向量服务区域。
3. 工作模式选择“强制云端”。此模式不要求本机安装 Ollama。
4. 在“豆包 Embedding API Key”中填入密钥，点击“保存并检测”。检测会发送一次极小的真实向量请求。
5. 等待显示“记忆向量服务检测通过”，并确认云端检测成功、维度为 1024。

当前云端接口对应豆包方舟，默认模型为 doubao-embedding-vision-251215。应确认账号具备该模型的调用权限；不能把 DeepSeek、OpenAI 或其他平台的 Key 直接填入这个位置。

### 三种模式如何选择

| 模式 | 适用情况 |
| --- | --- |
| 强制云端 | 不使用本地模型，使用豆包 Embedding；普通云端用户优先选此项 |
| 强制本地 | 已安装 Ollama，且本机已有 bge-m3 模型 |
| 自动 | 希望优先使用本地模型，本地不可用时尝试配置好的豆包云端 |

使用本地方案时，需单独安装并运行 Ollama，在终端执行 ollama pull bge-m3，再选择相应模式检测。云端用户可以跳过此步骤。

### 什么时候需要重新检测

保存时本地后端未启动、服务恢复、修正账号权限或额度后，可点击“重新同步并检测”。程序会先把本机保存的配置同步给后端，再判断服务是否真的可用。

对话与 Embedding 是两套模型配置，不一定需要两把不同 Key。同一平台的一把 Key 可能同时拥有两种权限，但仍需要在两个配置位置分别保存；不同平台应使用各自凭证。

不要频繁更换 Embedding 模型。不同模型产生的向量可能不处于同一语义空间，旧向量的检索效果会受影响。确需切换时，先备份数据，再规划历史向量迁移，不能仅凭维度相同判断兼容。

## 4 聊天 长期记忆与本地任务

完成两项模型配置后，先从普通聊天开始，再逐步使用文件和办公能力。建议新建会话处理不同主题，任务中明确给出目标、输入位置和输出要求。

### 长期记忆如何使用

长期记忆用于跨会话保留有价值的信息，当前会话上下文用于完成眼前的对话和任务，两者用途不同。对话中的每句话不一定都会成为长期记忆。

可以表达稳定的个人偏好，例如“请记住，我更喜欢先给结论，再解释原因”。之后在新会话中提出相关问题，观察回答是否结合已保存的信息。记忆写入和整理可能异步进行，不应把单次即时回答作为唯一判断依据。

在“记忆馆”或相关记忆管理入口查看保存的数据，必要时纠正不准确的信息。清空会话历史和执行上下文会保留长期记忆；删除长期记忆则是另一项操作，请核对确认提示。

### 给任务写清楚输入与交付物

- 文件任务：“读取 D:\材料\会议记录.txt，整理会议结论和待办事项，保存到 D:\材料\会议纪要.docx。”
- 办公任务：“根据我提供的销售表生成月度汇总，保留原表，把结果另存为新文件。”
- 查询任务：“查明天的天气，给出降雨概率和出行建议。”最新信息需要联网，是否能完成取决于网络和可用信息源。

### 工具权限与结果确认

Desktop 的基础本地工具由程序常驻提供，不需要通过外部 MCP 开关启用。涉及文件、终端或其他受控操作时，按界面提示审阅操作范围和目标路径，再决定是否允许。

任务结束后，以实际文件、执行结果和任务状态为准。遇到需要人工确认、第三方登录或验证码时，应按提示接管；不要仅根据一句“完成”就认定文件已经生成。

### 长任务与中断恢复

在“任务记录”中查看执行状态、结果或中断原因；界面提供“继续任务”时，可以尝试从记录继续。恢复能力取决于任务状态和外部条件，不能保证所有桌面操作都能无损重放。

长任务执行期间保持电脑唤醒、MindPet 运行、网络与相关应用可用。定时或后台任务同样依赖软件和本地服务运行，退出软件不等于任务仍会继续。模型多轮调用会累积 API 用量，可在内置统计中查看。

## 5 外部 MCP 与技能

MCP 用于连接第三方工具服务，Skill 用于提供某类工作的操作知识。首次配置时可以先跳过这两项，普通聊天和内置本地工具不依赖用户额外添加 MCP。

### 添加外部 MCP

1. 在“Agent → MCP 服务”中添加服务名称、准确的 MCP 接口地址、传输类型，以及服务要求的 Token。
2. 接口地址与认证方式以服务方接入说明为准。服务官网的根域名不一定就是 MCP 接口地址。
3. 保存后使用界面的连接检测，确认能获取工具目录。连接失败时先核对地址、Token、账号权限及网络。
4. 回到聊天输入框，输入“/”，从菜单选择本次任务需要的外部 MCP，再描述要完成的事情。

通过“/”选择外部服务是本次任务的能力选择。Desktop 是程序内置的本地工具来源，与用户配置的第三方 MCP 不同。

外部 MCP 可能访问第三方账号、读取数据或执行外部操作。选择前应了解服务来源和用途；涉及发布、修改或其他敏感操作时，认真阅读确认提示。

### 常见连接状态

| 状态 | 应如何处理 |
| --- | --- |
| HTTP 401 | 检查 Token 是否缺失、失效或认证方式不符合服务要求 |
| HTTP 403 | 服务或网关拒绝访问；核对接口、权限和访问限制，不能只靠重复重试 |
| 超时或连接失败 | 检查网络、服务地址与第三方服务是否在线 |
| 正在冷却 | 前一次连接失败后暂缓重试，等待冷却并先处理失败原因 |

某个外部 MCP 失败不等于整个 MindPet 不可用。日志中出现桥接层 HTTP 500 时，也应向前查找具体外部服务的原始错误。

### 导入和生成技能

进入“Agent → 技能加入”，可“导入技能包 (.zip)”或使用“AI 生成技能”。生成时写清技能名称、适用场景、输入要求和期望结果，检查生成内容后保存。

技能无需逐个勾选启用。程序根据任务发现相关技能，并按需加载正文；技能不是自动获得额外系统权限的方式。内置技能随服务提供，用户技能与内置技能共同参与任务匹配。只导入可信来源的技能包。

## 6 排障 升级与数据保护

### 先看哪个状态

| 现象 | 检查与处理 |
| --- | --- |
| 本地后端不可达 | 等待启动完成，检查默认地址及 8080 端口占用；先关闭多余的旧版 MindPet 或开发后端，再重启 |
| Key 已保存但没有生效 | 查看同步提示，确认后端可达后重新保存或同步；不要反复更换 Key |
| LLM 返回 401 或 403 | 核对当前服务地址、Key、模型权限；更换服务商后应重新填写凭证 |
| LLM 返回 429 | 检查额度、余额、并发与速率限制；按平台要求等待或调整 |
| Connection reset | 流式连接在网络、代理或服务端链路中被重置；检查网络和代理后重试，不能仅凭此判断 Key 错误 |
| 测试成功但聊天失败 | 普通测试与流式聊天链路不同；核对模型、网络、代理和接口对流式输出及工具调用的支持 |
| 向量服务尚未通过检测 | 确认选择了正确模式；云端用户检查豆包模型权限和额度，点击重新同步并检测 |

保留报错时间、服务名称、模型名称、HTTP 状态码和操作步骤，有助于定位问题。分享日志前遮盖 API Key、Token、含凭证的地址和个人内容。

### 安装完成后的确认清单

1. 本地后端连接可达，对话配置显示已同步。
2. LLM 连接测试通过，普通聊天也能实际回复。
3. 记忆向量服务检测通过；云端用户无需安装 Ollama。
4. 关闭并重新打开软件后，配置仍可恢复，无需再次粘贴 Key。
5. 如需外部 MCP，单独验证其工具目录与实际调用；基础使用可以不配置。

### 升级与备份

升级前通过托盘退出 MindPet，避免旧进程继续使用旧后端；然后运行新安装包。安装程序和用户数据目录是两个位置，普通更新不等于清空记忆，但重要数据仍应先备份。

安装版会优先把用户数据保存在 mindpet.exe 同级的 data 文件夹；安装目录不可写时，才退回 Windows 应用数据目录，通常为 %APPDATA%\mindpet。环境变量指定的用户目录或应用中单独选择的存储位置也可能改变相关数据位置，应以实际设置为准。完全退出软件后备份用户目录与自定义存储目录，连同数据库配套文件一起保留，不要在数据库正在写入时只复制单个文件。重装或更换安装目录前，尤其要先备份原安装目录的 data 文件夹。

密钥使用系统加密保护，直接把数据目录复制到另一台电脑，不保证凭证可以解密；迁移后可能需要重新填写 Key。使用云端模型时，对话或向量请求会发送到所选平台；采用本地存储不代表全部处理都离线。
