# MindPet 浅色模式配色重设计方案

## 1. 文档定位

本方案用于改善 MindPet 整个桌面端浅色模式的可读性与视觉层级，并重点处理“记忆星河”背景、记忆侧边栏和半透明面板在浅色背景下边界不清的问题。

本次只输出设计与实施方案，不修改代码。后续实现时应保留现有深色模式，不改变页面结构、交互流程、排版尺寸和功能逻辑。

## 2. 设计目标

浅色模式继续保持蓝白色、轻盈、灵动、简洁的视觉方向，同时解决以下问题：

- 应用背景、内容区、侧边栏和卡片之间有清晰但柔和的层级。
- 正文、辅助文字、占位文字和禁用文字在浅色背景上都能被快速读清。
- 蓝色主要承担操作、选中、焦点和信息提示，不把整页染成高饱和蓝色。
- “记忆星河”在浅色模式下仍有星空纵深感，照片、粒子和文字不会融进背景。
- 侧边栏保持轻盈，但导航项、当前状态和分隔边界更加明确。
- 全局页面与“记忆星河”使用同一套浅色语义，避免像两个独立产品。
- 正文、控件、图标和焦点状态满足 WCAG AA 的基本对比度要求。

## 3. 当前问题分析

### 3.1 全局浅色层级过于接近

当前全局浅色模式主要使用：

- 应用背景 `#f1f5f9`
- 内容背景 `#f8fafc`
- 侧边栏与卡片 `#ffffff`
- 边框 `#e2e8f0`

这些颜色都集中在接近白色的窄亮度区间。单独看较干净，但应用背景、侧边栏、内容区、卡片和输入框同时出现时，主要依靠很淡的边框区分，结构容易连成一片。

### 3.2 半透明表面叠加后进一步变淡

“记忆星河”大量使用透明或半透明表面，例如：

- `--cosmos-panel: rgba(249, 251, 255, 0.56)`
- `--cosmos-panel-strong: rgba(250, 252, 255, 0.82)`
- `--cosmos-sidebar: rgba(248, 250, 255, 0.7)`
- `--cosmos-input: rgba(255, 255, 255, 0.58)`

这些表面叠在本来就很亮的蓝白背景上，最终颜色非常接近，侧边栏、面板、按钮和输入框的轮廓不稳定。不同背景区域下，同一个透明颜色还会产生不同的实际对比度。

### 3.3 边框更像装饰，无法承担结构分隔

当前浅色边框大多接近 `#e2e8f0` 或透明蓝灰。它适合卡片内部的轻分隔，但不足以同时承担：

- 侧边栏与主内容区的边界；
- 输入框和页面背景的边界；
- 浮层、卡片与底层内容的边界；
- 当前导航项和普通导航项的状态差异。

需要把“普通分隔线”和“控件轮廓线”拆成两个强度等级。

### 3.4 文字层级虽有区分，但小字号仍显得发灰

当前系统存在多组浅色文字变量，并且在文件后部还有覆盖规则。`--text-muted`、`--cosmos-muted` 和一些硬编码灰色并不完全一致。10px 至 12px 的日期、状态、提示语在半透明面板上容易显得过淡。

### 3.5 记忆星河背景的色相关系不够集中

当前浅色星河同时混合浅蓝、灰紫和浅粉暖色。由于三者亮度接近，背景形成一层均匀的浅雾，星河中心、照片通道和外围空间的差异不明显。照片卡片周围的蓝色粒子在浅背景上也容易失去存在感。

## 4. 新的视觉方向

### 4.1 主题定义

新浅色主题命名为“澄空蓝白”。它应像有空气感的清晨天空：主体是干净的冷白和浅雾蓝，结构使用更沉静的蓝灰，交互使用清晰的中高饱和蓝。

视觉关键词：

- 澄澈
- 轻盈
- 有层次
- 安静
- 清晰

### 4.2 色彩关系

- 大面积应用背景使用低饱和雾蓝，不使用纯白铺满整个窗口。
- 主内容区比应用背景亮一层，保证阅读区域干净。
- 主菜单和聊天记录侧栏使用白色，通过清楚的边界形成稳定的导航锚点。
- 卡片、输入框和弹窗使用白色或接近白色的实色表面。
- 文字使用带蓝调的深灰，不使用纯黑，也不使用低对比度浅灰。
- 主蓝用于全局操作、当前状态、链接、焦点和重要信息。
- 金色保留原来的记忆语义，并继续用于“记忆星河”自己的当前导航、时间轴和焦点提示；不扩散到全局主操作。

### 4.3 对比范围

本方案使用“中等结构对比 + 高文字对比 + 克制的色彩剂量”：

- 结构层级通过 3 至 4 档蓝白表面建立。
- 正文和辅助文字之间有明确亮度差。
- 普通边框安静，控件边框更明确。
- 高饱和颜色只集中在交互状态，避免页面变得厚重。

| 信息 | `#2869D8` | `#DCEBFF` |

状态不能只用颜色表达，仍需保留图标、文字或形状提示。

## 7. 全局界面应用规则

### 7.1 应用外壳

- 窗口底色使用 `#EDF4FA`。
- 主内容区使用 `#F7FBFF`，与窗口底色形成温和层级。
- 内容页不再用多层接近白色的透明背景叠加。
- 主内容区和侧边栏之间使用 `#B5C6D6` 的实色边界。

### 7.2 主侧边栏

- 主菜单和聊天记录侧栏使用白色，通过清楚的边界与主内容区区分，不额外染成蓝底。
- 普通菜单文字使用 `#344B62`，辅助说明使用 `#536C84`。
- 悬停项使用 `#E1EDF8`，不依赖极低透明度蒙层。
- 当前项使用 `#D6E8FC`，文字和图标使用 `#194F96`，边框使用 `#8CB5E6`。
- 当前项应同时保留背景、文字和边缘标识，不能只通过蓝色文字表示。
- “新会话”按钮使用柔和蓝底和清晰蓝字；主按钮仍可使用实色主蓝。
- 折叠按钮、更多按钮等弱操作保持白色或透明底，悬停时出现明确蓝灰表面。

### 7.3 标题栏和标签页

- 标题栏与应用底色保持一致，减少额外色块。
- 未选中标签使用次级文字，悬停使用 `#E1EDF8`。
- 选中标签使用白色表面、`#C8D6E3` 边框和主文字色。
- 关闭按钮的危险色只在悬停和按下时出现。

### 7.4 聊天区

- 聊天主背景使用 `#F7FBFF`。
- Agent 消息表面使用白色，边框使用 `#C8D6E3`。
- 用户消息可以保留柔和蓝底，但文字必须使用 `#172A3D` 或满足对比度的深蓝。
- 工具结果、代码块和表格使用 `#EEF5FA`，避免与普通消息卡片完全相同。
- 时间、模型名、来源等元数据使用 `#536C84`，不再叠加额外透明度。

### 7.5 输入框和表单

- 输入框使用白色实色背景。
- 默认边框使用 `#7792AA`，确保控件边界在白色背景上可辨。
- 聚焦时边框变为 `#1E66D0`，外层增加 2px 至 3px 的浅蓝焦点环。
- 占位文字使用 `#536C84`；输入正文使用 `#172A3D`。
- 禁用状态使用 `#EDF1F5` 背景和 `#7B8C9D` 文字，不仅通过降低整体透明度表达。

### 7.6 卡片、菜单与弹窗

- 普通卡片使用白色表面和 `#C8D6E3` 边框。
- 可点击卡片悬停时改为轻蓝白表面，并提高边框蓝度。
- 菜单和弹窗使用接近不透明的白色表面；模糊只作为辅助，不承担可读性。
- 浮层使用明确阴影和结构边框，避免白色弹窗融入白色页面。
- 遮罩层使用带蓝调的深灰透明色，例如 `rgba(23, 42, 61, 0.38)`。

## 8. “记忆星河”浅色模式专用方案

### 8.1 页面语义变量

“记忆星河”保留独立变量，但应映射到全局浅色主题，不再形成另一套互不关联的灰蓝色。

| 变量 | 建议值 | 说明 |
| --- | --- | --- |
| `--cosmos-ink` | `#18304A` | 标题与核心内容 |
| `--cosmos-ink-soft` | `#334F69` | 正文与次级标题 |
| `--cosmos-muted` | `#536C84` | 日期、说明和元数据 |
| `--cosmos-faint` | `#E6F0F8` | 轻量按钮和局部底色 |
| `--cosmos-line` | `#B7CADB` | 普通结构边界 |
| `--cosmos-blue` | `#719BB8` | 星点、空间光和次级图标 |
| `--cosmos-violet` | `#A89BC2` | 少量远景冷紫层次 |
| `--cosmos-gold` | `#BA8D58` | 恢复原有的记忆、星尘和当前状态强调色 |
| `--cosmos-gold-soft` | `rgba(186,141,88,.14)` | 金色提示的浅背景 |
| `--cosmos-green` | `#6F9F92` | 本地保存与在线状态 |
| `--cosmos-panel` | `rgba(255,255,255,.84)` | 普通玻璃面板 |
| `--cosmos-panel-strong` | `rgba(255,255,255,.96)` | 弹窗和重要卡片 |
| `--cosmos-sidebar` | `rgba(231,240,248,.96)` | 记忆页侧边栏 |
| `--cosmos-input` | `#FFFFFF` | 输入与表单 |
| `--cosmos-shadow` | `rgba(39,74,108,.16)` | 普通阴影 |
| `--cosmos-shadow-strong` | `rgba(30,61,94,.26)` | 浮层阴影 |

恢复原来的浅金色 `#BA8D58` 与柔金底色。它用于星尘、记忆标记、情绪标题，以及“记忆星河”内部的当前导航和时间轴状态。主应用侧边栏、全局主操作和普通系统焦点仍使用蓝色。

### 8.2 星河背景

推荐背景：

```css
background:
  radial-gradient(ellipse at 18% 14%, rgba(255,255,255,.92), transparent 34%),
  radial-gradient(ellipse at 78% 28%, rgba(122,165,207,.28), transparent 42%),
  radial-gradient(ellipse at 48% 82%, rgba(70,126,177,.24), transparent 48%),
  radial-gradient(ellipse at 58% 46%, rgba(136,135,183,.12), transparent 38%),
  linear-gradient(135deg, #eaf4fb 0%, #dceaf5 48%, #e6edf8 74%, #f3f7fb 100%);
```

调整原则：

- 背景基底比当前略深，让白色面板和照片卡片能够浮起来。
- 蓝色雾层承担主要空间深度，紫色只作为少量远景层次。
- 移除明显的浅粉区域，避免蓝白主题被稀释。
- 中心行进通道保持更亮，左右照片区域和远景略深。
- 中轴光带在上下端向星场透明渐隐，避免直角裁切形成可见边线。
- 噪点纹理透明度控制在 `0.05` 至 `0.07`，避免浅色模式产生灰脏感。

### 8.3 星点与粒子

- 远景星点使用 `#5D89B0`，静态透明度建议为 `0.34` 至 `0.58`。
- 中景粒子使用 `#477EA9`，透明度建议为 `0.42` 至 `0.72`。
- 暖色星尘使用原有记忆金色 `#BA8D58`，数量不超过整体可见粒子的 18%。
- 近景粒子允许出现接近白色的核心，但必须有蓝色或金色外晕，避免消失在亮背景中。
- 光标核心外圈使用更深的 `#3D729F`，保证在背景最亮区域仍然可见。
- 照片周围的粒子亮度可以高于背景粒子，但粒径和数量保持克制。

### 8.4 照片卡片

- 照片卡片边缘增加一层 `rgba(255,255,255,.72)` 的内高光和一层 `rgba(45,82,116,.24)` 的外轮廓。
- 默认阴影使用 `0 18px 46px rgba(38,67,96,.24)`。
- 最近照片使用更清晰的边缘和轻微蓝色轮廓，不通过扩大白色光晕突出。
- 图片底部文字蒙层保持深色，确保日期和标题在各种照片上都可读。
- 照片加载失败的占位背景使用 `#E1ECF5` 至 `#D4E3EF` 的蓝灰渐变。

### 8.5 记忆页侧边栏

- 背景使用接近实色的 `rgba(231,240,248,.96)`，保留轻微玻璃感。
- 与场景之间使用 `#B7CADB` 边界，不能只依靠背景差异区分。
- 普通导航文字使用 `#536C84`，标题使用 `#18304A`。
- 悬停项使用 `#DDEAF5`。
- 当前项沿用原来的金色柔和表面和金色左侧指示条，文字继续使用高对比度深蓝灰。
- 分享按钮继续使用原来的深金色 `#94611E`，保证白底上的文字对比度。
- 本地保存状态的绿色提高明度对比，并配合圆点与文本表示状态。

### 8.6 顶部标题、导航和时间轴

- 页面主标题使用 `#18304A`，描述使用 `#536C84`。
- 顶部相邻导航和底部时间轴使用 `rgba(255,255,255,.88)`，边框使用 `#B7CADB`。
- 时间轴轨道使用 `#AFC4D6`，已浏览进度使用金色与星河蓝的混合色，当前节点使用 `#BA8D58`。
- 时间节点不能只通过极淡的发光区分；当前节点应同时改变尺寸、实色和轮廓。
- 日期和辅助说明不低于 `#536C84` 的可见强度。

### 8.7 “MindPet 记得”内容区

- 内容壳使用 `rgba(247,251,255,.92)`，与星河背景形成清楚的阅读表面。
- 展开卡片使用白色，边框使用 `#C2D2E0`。
- MindPet 的想法使用主文字 `#18304A`，原文和上下文使用 `#334F69`。
- “查看原文”按钮保持小型胶囊样式，默认背景使用 `#E6F0F8`，文字使用 `#536C84`；悬停后使用 `#DCEBFF` 和 `#194F96`。
- 输入区使用白色实色背景和清晰控件边框，避免与内容卡片混在一起。

### 8.8 弹窗与分享流程

- 分享弹窗和详情弹窗使用 `rgba(255,255,255,.97)`，不使用过低透明度。
- 弹窗边框使用 `#B5C6D6`，浮层阴影使用全局浮层阴影。
- 日期选择器、文本框和情绪按钮统一使用全局控件边框与焦点蓝。
- 分享主按钮使用白底、`#94611E` 文字和实色边框；星河内的导航状态继续使用浅金色，系统主操作仍使用主蓝。

## 10. 交互状态规范

### 10.1 默认

- 普通内容以中性蓝灰和白色表面为主。
- 不使用主蓝填充无交互意义的装饰区域。
- 辅助文字保持可读，不以透明度制造层级。

### 10.2 悬停

- 背景从白色或透明变为 `#E1EDF8`。
- 可同时轻微提高边框蓝度。
- 不依赖位移和阴影表达所有悬停状态。

### 10.3 选中

- 使用 `#D6E8FC` 背景、`#194F96` 文字和 `#8CB5E6` 边框。
- 导航项保留位置标记或图标变化，避免只用颜色传达。

### 10.4 聚焦

- 使用 `#1E66D0` 的 2px 清晰轮廓。
- 焦点环与控件本身保持至少 2px 的可见范围。
- 不移除浏览器焦点后只保留阴影。

### 10.5 禁用

- 使用 `#EDF1F5` 背景、`#7B8C9D` 文字和 `#C8D6E3` 边框。
- 可降低装饰图标亮度，但正文和状态说明仍需可读。

## 12. 响应式与窗口尺寸

- 窄窗口下侧边栏变为顶部导航时，顶部区域继续使用白色，下边界使用 `#B5C6D6`。
- 小尺寸界面不能通过进一步降低透明度来减少视觉重量。
- 触摸目标尺寸、文本大小和现有布局保持不变，配色调整不能造成按钮内容拥挤。
- 星河在窄屏中减少粒子数量时，保留中景蓝粒子和照片轮廓，优先移除低价值远景装饰。

## 13. 性能要求

- 全局表面优先使用实色，减少多层 `backdrop-filter` 和透明背景叠加。
- 星河渐变层数量控制在 4 至 5 层，不增加持续动画的大面积模糊层。
- 阴影只用于抬升表面，避免为大量列表项同时绘制大范围阴影。
- Canvas 粒子继续从 CSS 变量读取主题色，不为浅色模式创建第二套粒子循环。

## 14. 不修改的内容

- 不改变深色模式的现有配色和视觉结构。
- 不修改字体、字号体系和页面布局。
- 不修改记忆星河的相机、滚轮、照片排布和粒子运动逻辑。
- 不修改“MindPet 记得”的数据、文案生成和保存逻辑。
- 不引入新的品牌色、插画、纹理图片或外部素材。
- 不将所有按钮改成高饱和蓝色。

## 15. 验收标准

- 浅色模式下，用户能一眼分辨应用底色、侧边栏、主内容区、卡片和输入框。
- 主文字、正文、辅助文字和禁用文字形成稳定的四级层次。
- 侧边栏普通项、悬停项和当前项无需依赖鼠标移动也能被区分。
- 输入框、选择框和按钮在白色卡片中仍有明确边界。
- 全局主操作、侧边栏选中和普通焦点使用统一蓝色语义；“记忆星河”内部保留原来的金色当前态。
- 记忆星河浅色背景具有清楚的中心通道、外围空间和远近层次。
- 星点、星尘光标、照片轮廓和时间轴在背景最亮区域仍然可见。
- “MindPet 记得”的内容卡片、原文区域和输入区层级清楚。
- 普通正文达到 4.5:1，对大文字达到 3:1，控件边界、图标和焦点指示达到 3:1。
- 浅色模式在长时间观看时保持柔和，不出现大片纯白刺眼区域或高饱和蓝色铺满页面。
- 深色模式在实施后没有视觉回归。

## 16. 实施注意事项

- 先改语义变量，再处理确实无法映射的局部颜色。
- 不要把现有所有透明色机械替换为同一个实色，应按表面层级选择对应角色。
- `color-mix()` 应只用于可控的状态变化，不用于正文对比度和输入框边界等关键可读性场景。
- 对所有硬编码 `#ffffff`、浅灰和低透明度背景进行一次清单检查，确认它们属于“抬升表面”还是历史遗留。
- 记忆页的金色用于记忆语义和星河内部状态，不代替全局主操作蓝。
- 完成实现后，应以真实截图和浏览器计算样式验证，不以色板本身判断完成。
