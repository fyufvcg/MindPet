# 记忆星图本地演示

`seed-50-nodes.sql` 创建 50 个明确标注为虚构的演示节点、63 条事实关系及 50 条来源记录。现有图谱接口会通过合成向量生成最多 80 条语义相似线。记录包含不同重要度和最后提及时间，可查看清晰、渐淡和微弱三档效果。

星图亮度是前端依照当前图谱保留度公式计算的展示估算；它不会改变检索结果或遗忘状态。后端低于阈值、已经不返回的节点不会通过前端重新显示。随后增加的手动建图入口使用独立后端写入服务，检索和遗忘规则保持原样。

## 执行

1. 确认数据库包含 `kg_entity`、`kg_relation` 和 `kg_evidence`。使用实际后端正在使用的 SQLite 文件，或者复制该文件用于单独演示。
2. 用 SQLite 数据库工具打开文件，执行 `seed-50-nodes.sql` 的全部内容。该脚本是一个事务，可以重复执行，只替换 `mindpet-ui-demo-` 前缀记录。
3. 打开记忆星图，点击“刷新图谱”。先查看总览，再点击“科幻小说”查看实线与虚线的区别；点击“春日展览”查看微弱记忆的亮度和详情。
4. 展示结束后执行 `cleanup.sql`，再次刷新。清理仅针对上述前缀及关联记录。

如果已有 SQLite CLI，可执行（将路径替换为实际数据库绝对路径）：

```powershell
Get-Content -Raw -Encoding UTF8 'D:\youkeda\MINDPET\docs\ui\memory-star-map\seed-50-nodes.sql' | sqlite3 'D:\实际目录\mindpet.db'
Get-Content -Raw -Encoding UTF8 'D:\youkeda\MINDPET\docs\ui\memory-star-map\cleanup.sql' | sqlite3 'D:\实际目录\mindpet.db'
```

演示脚本不会写入长期记忆、检索单元、画像或馆长记录。但图谱本身也是检索来源，因此若导入日常数据库，在清理前这些虚构节点可能进入图谱上下文。合成的 8 维向量用于视觉验证，不适用于真实模型检索；建议用数据库副本演示，或看完立即清理。

## 已验证

- 在临时 SQLite 数据库上执行两次，节点仍为 50 个，无重复插入。
- 外键检查通过，演示关系均有有效端点。
- 节点保留度约为 0.13–0.96，均高于当前图谱返回阈值 0.1。
- 按现有余弦相似度阈值 0.76 和上限 80 验证了语义关系生成。
- 执行清理后演示实体、关系、证据全部移除。

脚本尚未对用户实际数据库执行。
