# MindPet 云服务器部署方案（不含 Ollama / 只发 Electron 前端）

> 结论先行：**能放服务器的都放，但「桌面端本地工具桥」放不了。**
> 用户最终拿到的是一个约 300–400MB 的 Windows 安装包，双击装完就能聊天、有记忆、有桌宠；
> 但「操作我这台电脑」那部分能力（截图、终端、Office 生成、RPA、电脑操控）在纯云部署下会失效，
> 需要按第 6 节做改造或取舍。服务器按 **2核4G / 50G SSD** 起步即可，月付约 ¥65–75。

---

## 1. 服务器配置推荐

### 1.1 内存实测预算（不启 Ollama）

| 组件 | 常驻内存 |
|---|---|
| Spring Boot 后端（`-Xmx768m` + Metaspace + 线程栈） | 1.0 – 1.4 GB |
| PostgreSQL 16 + pgvector | 250 – 400 MB |
| Redis 7 | 60 – 100 MB |
| Docker daemon + 镜像层 | 150 – 250 MB |
| 系统 + sshd | 200 – 300 MB |
| **合计基线** | **约 1.7 – 2.4 GB** |

峰值场景要额外留量：
- 开 `search`/`browser` 组走服务端 Playwright 时，Chromium 一个实例 **300–600MB**（当前 `compose.yaml` 里 `BROWSER_AUTOMATION_ENABLED=false`，容器内也没装浏览器，所以默认不会吃这块）；
- 记忆/知识图谱批量重建、记忆馆长（MemoryCurator）触发时会短时抬升 CPU。

### 1.2 三档配置

| 档位 | 配置 | 适用 | 参考价 |
|---|---|---|---|
| ❌ 别买 | 2核2G | **会 OOM**。基线 2.2G 已经贴顶，Docker 一下就把 Postgres 或 JVM OOM-kill | — |
| ✅ 最低可用 | **2核4G / 50G SSD / 200M峰值带宽** | 自己用 + 2~5 个朋友，同时 5–8 路对话 | 腾讯云轻量 ¥65/月（50G 盘）或 ¥72/月（60G 盘） |
| ✅ 推荐 | **4核8G / 80–120G SSD** | 10 人以上 / 想开服务端浏览器 / 长期跑 | 腾讯云轻量锐驰型 4核8G ¥230/月；想压在 200 以内选阿里云 ECS 通用算力型 u1（2核4G ¥199/年新购，或 4核8G 活动机型）或雨云等二线厂商 4核8G ≈ ¥200/月 |

**一句话推荐**：先买 **腾讯云轻量 2核4G（50G 盘，¥65/月）** 跑通，实测内存水位 >85% 再升配。
这个价位离你的 ¥200 预算上限还有很大空间，剩下的钱建议留给 LLM/Embedding 的 token 费用。

### 1.3 磁盘与网络

- **磁盘**：系统 8G + Docker 镜像（pgvector pg16 ≈ 400MB、redis ≈ 40MB、temurin-jre ≈ 250MB、后端 jar 66MB）+ 日志 + 数据库。
  50G 能用，但长期存储建议 **60–80G**；`generated_files`、日志、pg 数据都在涨。
- **带宽**：聊天是 NDJSON 流式小包，一次对话约 20–50KB，**200G/月流量对几十个用户完全够**。
  反向代理记得 `proxy_buffering off`，否则流式输出会被缓冲成一次性吐出来。
- **CPU**：主要负载是等 LLM 的 I/O，不是算力。2 核足够 5–8 路并发对话。
- **数据库增长**：一条长期记忆 ≈ 内容 + 1024 维向量（约 4KB），1 万条 ≈ 40–60MB，很轻。
  真正会涨的是 `session messages`（Redis 短期 200 条/会话，7 天 TTL，不会无限涨）。

### 1.4 云厂商参考

- [腾讯云轻量应用服务器价格总览](https://cloud.tencent.com/document/product/1207/73452)：锐驰型 2核4G/50G = ¥65/月，2核8G/80G = ¥105/月，4核8G/120G = ¥230/月（200M 峰值、无限流量）
- [阿里云轻量 2核4G 9.9元/月、199元/年（新用户抢购）](https://developer.aliyun.com/article/1734171)；ECS 通用算力型 u1 2核4G ¥199/年、新购续费同价（需企业实名）
- 4核8G 的 ¥200/月 档位：[雨云宿迁 9950X 4核8G ≈ ¥200/月](https://blog.zeruns.com/archives/809.html)（二线厂商，注意数据安全与合规风险）

## 3. 两种部署形态共用一个客户端（地址注入）

评委有两种选择：**自己 Docker 本地部署**（后端在 `127.0.0.1:8080`）或**直接用云服务器**（后端在远程地址）。
两者地址不同，所以客户端**不能把地址编译时写死**，必须在运行时解析。

### 3.1 已实现的地址解析（`src/main/backend-endpoint.ts`）

优先级从高到低：

| 优先级 | 来源 | 用途 |
|---|---|---|
| 1 | 命令行 `--backend=https://xxx` | 临时切换 / 快捷方式 |
| 2 | 环境变量 `MINDPET_SERVER_URL`（兼容旧名 `XIAOQING_API_URL`） | 运维/脚本注入 |
| 3 | `server.json`（`<userData>/server.json` 或 **exe 同级** `server.json`） | 持久化，设置页写入；也是"绿色分发"的预置手段 |
| 4 | 内置默认 `http://127.0.0.1:8080` | 本地部署零配置 |

> 打包后 `userData` 就是 exe 同级的 `data/`（项目已有的便携模式），
> 所以 `server.json` 放在 exe 旁边即可生效——云端形态可以直接压一个
> 「安装包 + `{"backendUrl":"https://你的域名"}`」的 zip 发给评委。

### 3.2 客户端已经做的事

- `backend-api.ts`、`index.ts`（21 处）、`http-run-repository.ts`、`mcp-server.ts` 的硬编码地址**全部替换**为 `backendUrl(path)` / `backendBaseUrl()`；
- 错误提示文案改为动态地址（否则连云端失败时还提示 `127.0.0.1:8080`，会让评委误以为客户端坏了）；
- 设置页新增「**后端连接**」子页：显示当前生效地址、输入框、**测试连接**、**保存并生效**、**恢复默认（本机）**；
  保存写入 `server.json` 并立即生效（同一进程内后续请求用新地址）。

### 3.3 已知边界（UI 里已提示）

- 切换到远程后端后，「操作本机电脑」类能力不可用（原因见第 4 节），聊天/记忆/图谱不受影响；
- 通知轮询等少数在启动时读取地址的模块，**切换地址后建议重启一次客户端**。

### 3.4 本地部署路径不受影响

默认值仍是 `http://127.0.0.1:8080`，`docker/compose.yaml` 一个字不用改，本机玩法完全保留。

## 4. 后端能全部放服务器吗？——按能力拆开看

关键事实：**桌面端工具是通过「Electron 在本机开的 MCP HTTP 服务」暴露给后端 LLM 的**
（`MindPet/src/main/tools/mcp/mcp-server.ts`，监听 `127.0.0.1:9339`，
注册名 `desktop__{category}__{toolName}`，后端 `AiService` 按 category 分组路由）。
后端调它的方式是 `POST http://127.0.0.1:9339`。

**后端一旦上云，这个 `127.0.0.1` 就指向服务器自己，永远连不上用户电脑。**

| 能力 | 现在跑在哪 | 云端可行性 |
|---|---|---|
| 聊天、LLM 调用、意图路由、情感分析 | Java 后端 | ✅ 全部上云（只留一个 LLM Key 在服务器） |
| 长期记忆 / 用户画像 / 知识图谱 / 会话 | Java + PG + Redis | ✅ 全部上云 |
| 天气 / 腾讯地图 / 滴滴 / 12306 / 邮件 / 发票 / 图表 | Java 后端（纯 HTTP 出网） | ✅ 全部上云 |
| Embedding | 豆包 API（AUTO 模式无 Ollama 时自动降级豆包） | ✅ 上云，服务器不需要 Ollama |
| Skill / MCP 配置管理 | Java 后端 | ✅ 上云（每个用户需要隔离） |
| **文件/Office/终端/SSH/电脑操控/系统信息/RPA** | **Electron 主进程**（`src/main/tools/builtin/*`，经 MCP 桥给后端） | ❌ **上不了云**，见下 |
| 微信 Bot / QQ Bot / 本地会议录音 | Electron 主进程 + `resources/asr/*.py` | ⚠️ 要常驻在线，只能跑在「一直开机」的机器上，不能跟用户桌面绑定 |
| 后端「本地文件工具」 | 已不在 Java 侧（README 里提到的 `LocalFileTool` 在当前代码中不存在） | — |

> 也就是说：**后端本身可以 100% 上云，但"操作用户电脑"这条链路必须留在客户端，并在云端断开。**

### 4.1 桌面工具桥的三种处理方式

1. **推荐：混合模式**——Electron 仍在用户本机起 MCP 服务，后端不再直连 `127.0.0.1`，
   而是通过 Electron 主动建立的反向通道（WebSocket / 长轮询）下发工具调用、回收结果。
   需要改：`backend-api.ts` 增加工具事件通道；`mcp-server.ts` 改成不依赖入站连接；
   后端 `McpManager` 增加一类「远程桌面工具」provider。
2. **过渡：本机模式**——需要完整本地能力的用户，仍然本机跑后端（现有 `docker compose` 那套照旧），
   云端只服务「只聊天 + 记忆」的用户。零改造，但要维护两套形态。
3. **临时：云端禁用桌面工具组**——把 `AiService` 的 `TOOL_GROUPS` 里
   `终端 / 电脑操控 / 文档处理 / 系统 / 自动化` 在云端 profile 下移除，避免 LLM 调用后 5 秒超时返回
   「MCP 无响应」这种糟糕体验。**这一步必须做，否则云端聊天会出现莫名其妙的报错话术。**

## 4. 部署到服务器需要改的地方（改造清单）

| # | 位置 | 现状 | 云端要改成 |
|---|---|---|---|
| 1 | `MindPet/src/main/backend-api.ts:72` | `process.env.XIAOQING_API_URL \|\| 'http://127.0.0.1:8080'` | 打包时注入公网地址（或改成读取用户配置项） |
| 2 | `MindPet/src/main/index.ts` 有 **23 处**硬编码 `http://127.0.0.1:8080`（会话、记忆、技能、embedding、MCP 配置、通知轮询…） | 本地写死 | 全部抽成一个可配置常量；只改 backend-api.ts 是**不够**的 |
| 3 | `MindPet/src/main/rpa/persistence/http-run-repository.ts:22` | 写死 `127.0.0.1:8080/api/desktop/rpa` | 同步改 |
| 4 | `MindPet-java/src/main/resources/application.yml` | 明文 Ark/DeepSeek Key、腾讯地图 Key、百度 Key、QQ 邮箱授权码、`D:/youkeda/2026年报销.xlsx`、`C:/Users/17547/Desktop` | **必须全部移除**：改用环境变量/compose 注入；这份 yml 会被打进 66MB 的 jar 里，公网一泄露就是全套凭证 |
| 5 | `userId` | 全端写死 `desktop-user`（`DESKTOP_USER_ID`） | 加真实用户标识，否则**所有用户的记忆、画像、会话混在一个池子里**（隐私事故） |
| 6 | `MindPet-java/src/main/java/config/WebConfig.java` | `allowedOriginPatterns("*")` + `allowCredentials(true)` | 收紧白名单 |
| 7 | 后端 API | 无鉴权，任何知道 IP 的人都能调 | 加 API Token / 反向代理层 Basic Auth，至少加限流 |
| 8 | SSE/NDJSON 长连接 | 前端超时 120s，Nginx 默认 60s | Nginx：`proxy_read_timeout 300s; proxy_buffering off;` |
| 9 | 请求体大小 | 图片走 base64 塞 `images[]`，几 MB 很正常 | 调 `server.tomcat.max-http-form-post-size` / `max-swallow-size` |
| 10 | 生成文件落盘 | `System.getProperty("user.home")/.mindpet/generated-files`（容器内 = `/root/.mindpet`） | 挂卷持久化，否则容器重建文件全丢 |
| 11 | `docker/compose.yaml` 端口 | `"${BACKEND_PORT:-8080}:8080"`（所有网卡） | 改成 `127.0.0.1:8080:8080`，统一走 Nginx 443 |

### Nginx 反代要点（流式必须）

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;          # 关键：否则 NDJSON 会被攒成一坨
    proxy_cache off;
    proxy_read_timeout 300s;
    client_max_body_size 32m;     # 图片 base64
}
```

## 5. 用户最终得到的效果

**安装与首次启动**
1. 从你的下载链接拿到 `mindpet-1.0.0-setup.exe`（约 300–400MB），双击安装，可选安装目录，桌面自动生成快捷方式。
2. 首次打开：**不需要装 Java、Postgres、Redis、Docker、Ollama，也不需要填任何 API Key**（都活在服务器上）。
3. 直接进入聊天页 + Live2D 桌宠，`/api/desktop/health` 走公网地址；设置页显示 LLM / Embedding 的连通状态。

**日常使用**
- 聊天流式输出（逐字返回）、桌宠表情跟着情绪走、语音播报（`node-edge-tts`，本机出网）。
- **记忆是真的**：关掉应用第二天再开，它记得上次聊的事、你的偏好、情绪趋势；换一台电脑登录同一个账号，记忆是同一份（前提是做了第 4 节的用户隔离）。
- 知识图谱页能看到记忆星图，能溯源、能手动删。
- Skill（Markdown 技能）、MCP（外部工具 URL）在设置页可配。

**会在云端失效 / 表现明显变差的部分（务必提前告知用户）**
- ❌ 「帮我截个图 / 打开我电脑上的 Excel / 跑一下这个命令 / 自动点鼠标」——云端后端够不到用户电脑。
- ❌ 本地文件读写、Office 文档生成、RPA 工作流执行。这些能力**代码在 Electron 里是完整的**，缺的只是「后端 LLM 怎么指挥它」的那条链路（第 4.1 节方案 1）。
- ⚠️ 服务端「联网搜索/浏览器」如果 `BROWSER_AUTOMATION_ENABLED` 仍是 `false`，只有纯 HTTP 抓取可用。
- ⚠️ 微信/QQ Bot 需要一台常开的机器跑，用户的笔记本合盖就掉线。
- ⚠️ 多人共用一个云后端时，`desktop-user` 不分账号 = 记忆串台（上线前必须解决）。

## 6. 现在项目里哪些要打包成 Electron 安装包

**结论：只打包 `MindPet/` 这一个目录，产出 Windows 安装包。Java 后端 / 数据库 / Docker 一个都不进安装包。**

### 6.1 产物

| 命令 | 产物 |
|---|---|
| `cd MindPet && npm run build:win` | NSIS 安装包 `mindpet-1.0.0-setup.exe`（安装/卸载/桌面快捷方式，允许改安装目录） |
| `npm run build:unpack` | 免安装绿色目录（调试用） |
| `npm run build:mac` / `build:linux` | dmg / AppImage+snap+deb（可选） |

### 6.2 打包内容明细

| 进包 | 内容 | 来源 |
|---|---|---|
| ✅ | 主进程代码（含工具系统、MCP Server、RPA、微信/QQ Bot、本地运行时） | `src/main` → `out/main`（约 12MB JS） |
| ✅ | preload 桥 | `src/preload` |
| ✅ | React 渲染层 / 页面 / Live2D 渲染逻辑 | `src/renderer` → `out/renderer` |
| ✅ | Live2D 模型 + Cubism Core | `resources/live2d/**`（4.5MB，`asarUnpack: resources/**`） |
| ✅ | 应用图标 | `resources/icon.png` |
| ✅ | ASR 脚本 | `resources/asr/*.py`（**要用户自己有 Python 才能真跑**，当前项目没打进 Python 运行时） |
| ✅ | 原生依赖 | `sqlite3`、`@napi-rs/canvas`、`@nut-tree/nut-js`（按平台重新编译，`npmRebuild: false` 时直接复用预编译产物） |
| ✅ | Electron 39 运行时 | 自动下载（配置了 npmmirror 镜像） |
| ❌ | `MindPet-java`（66MB jar）、JDK | 服务器 Docker 里跑 |
| ❌ | PostgreSQL / pgvector / Redis / Ollama | 服务器 Docker 里跑 |
| ❌ | `docker/`、`scripts/*.bat`、根目录 `data/` | 运维脚本，不面向终端用户 |

预计安装包 **300–400MB**（Electron 运行时约占大头），安装后占用 **600–900MB**。

### 6.3 `electron-builder.yml` 上线前要修的坑

1. `nsis.installerIcon: build/icon.ico` —— 当前 `MindPet/build/` 只有 0.2MB 内容，**确认 `icon.ico` 存在**，否则打包直接报错。
2. `appId: com.electron.app`、`author: cheer.com`、`homepage` —— 仍是脚手架默认值，应改成真实身份（影响安装目录、卸载项、系统防火墙提示）。
3. `publish.url: https://example.com/auto-updates` —— 自动更新指向示例域名，要么配真实更新服务器，要么关掉。
4. `mac.notarize: false` —— 出 mac 包用户会被 Gatekeeper 拦，需要签名（不在本次范围）。
5. `files` 的排除规则没有排除 `.env`/`*.log`/`*.png` 调试截图，建议清理后再发。
6. 后端地址注入：**已完成**（见第 3 节）——设置页「后端连接」可直接填服务器地址，或用 `server.json` 预置；不再依赖用户手配环境变量。
