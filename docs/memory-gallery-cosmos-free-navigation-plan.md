# 回忆星河自由穿行与星尘动效方案

## 1. 文档定位

本方案只调整“回忆星河”，不修改“MindPet 记得”、照片分享流程、照片详情内容和本地存储规则。

本方案替代 `memory-gallery-redesign-plan.md` 中关于回忆星河滚轮吸附、分页计数、固定卡片间距和静态场景光标的设计。保留原方案中的双侧照片长廊、照片日期与简短标题、详情层、键盘可访问能力。

## 2. 目标

回忆星河应像一段可以自由穿行的星空记忆带，而不是一次切换一张照片的 3D 轮播。

- 用户通过鼠标滚轮或触控板连续前进和后退，可以停在任意纵深位置。
- 场景具有明显的星河粒子、纵深流动和速度反馈，同时保持照片清晰可读。
- 照片在左右两侧形成更紧凑、更自然的记忆群落，整体纵深比当前实现更远。
- 光标改为一颗轻盈的星尘核心，并在场景中留下短距离、会消散的粒子拖尾。
- 动效服务于空间方向和操作反馈，不遮挡照片，不制造持续强光或眩晕。

## 3. 当前体验需要修正的部分

### 3.1 移动仍像分页

当前相机使用照片索引作为位置，停止滚动后会吸附到最近索引，并显示“当前张数 / 总张数”。用户只能明显停在第 1、2、3 张等离散位置，无法在两组照片之间自由观察星河。

### 3.2 照片排布松散且纵深不足

当前照片左右距离偏大，每个深度层只有一张照片，连续照片之间的纵深间距较大。近处照片容易贴近左右边缘，远处照片数量又不足以形成深邃的星河通道。

### 3.3 星空缺少运动层次

现有星点主要是背景闪烁，与用户前进、后退和速度没有明显关系。滚动时缺少近景粒子掠过、中景星尘移动、远景缓慢漂移的视差反馈。

### 3.4 光标仍是普通指针变体

当前光标是带星点的箭头图形，仍然强调“点击”。它没有与星河运动形成联系，也没有体现用户正在星空中穿行。

## 4. 核心体验原则

### 4.1 连续空间

相机位置使用连续世界坐标，不再使用照片索引作为相机坐标。照片有自己的世界坐标，相机可以停在任意两张照片之间。

### 4.2 照片优先

粒子、薄雾、拖尾和光带只能帮助用户感知方向。照片、日期和标题始终是画面中对比度最高、信息最稳定的元素。

### 4.3 有惯性但可控制

滚动结束后允许短暂滑行，但不自动吸附照片。用户反向滚动时应立即减速并改变方向，不能出现难以停止的漂移。

### 4.4 深邃但不空旷

通过更密的照片节奏、更远的可视距离和多层粒子建立纵深。不要通过加大照片之间的空白来制造深度。

## 5. 空间结构

### 5.1 坐标系统

- 相机固定在画面横向中心，只沿 Z 轴移动。
- `cameraZ` 使用连续数值保存当前位置。
- `velocityZ` 保存当前移动速度。
- 最新记忆位于起点附近，向前进入更早的记忆，向后回到更新的记忆。
- 最前和最后仍有内容边界，但边界前后各保留一段星空缓冲区，避免第一张和最后一张照片贴住停止点。
- 用户到达边界时使用阻尼逐渐停止，不回弹到某张照片，不跳转到另一端。

### 5.2 照片分组

照片不再严格执行“一层一张、左右完全交替”。建议使用 2 至 4 张组成一个记忆组：

- 一个记忆组占用相对短的纵深区间。
- 同组照片可以是左 1 右 1、左 2 右 1或左 1 右 2。
- 同一侧连续出现两张时，必须改变高度、横向距离和旋转角度，避免遮挡。
- 组与组之间保留比组内更大的间距，形成呼吸节奏。
- 不允许三张大图同时占据画面中心读图区域。

推荐的初始空间参数：

| 项目 | 建议范围 | 目的 |
| --- | --- | --- |
| 组内照片 Z 间距 | 180 至 260 世界单位 | 让照片更紧凑 |
| 记忆组间距 | 320 至 460 世界单位 | 保留节奏变化 |
| 左右中心距离 | 画面宽度的 17% 至 24% | 减少照片贴边 |
| 高度变化 | 中心线上下 8% 至 18% | 形成自然悬浮感 |
| 面向中心旋转 | 18° 至 30° | 保证照片正面朝向用户 |
| 单张随机旋转 | 不超过 ±2° | 避免机械排列 |
| 可见纵深 | 当前视点前后约 16 至 24 个照片节点 | 建立更远纵深 |

这些数值应由统一的场景配置管理，不能散落在 JSX 和 CSS 中。

### 5.3 稳定的伪随机布局

照片位置变化应由照片 ID 生成稳定种子。同一批照片每次进入页面时保持相同位置，不应因刷新而重新跳动。

稳定种子只决定以下小幅变化：

- 左右侧选择；
- 组内位置；
- 高度；
- 横向距离；
- 小角度旋转；
- 卡片尺寸档位。

布局生成后必须执行碰撞检查。相邻可见照片的投影视图重叠超过约 20% 时，优先调整高度，其次调整纵深，最后调整横向距离。

### 5.4 照片视觉

- 长廊卡片仍只显示照片、日期和简短标题。
- 近处照片保持完整清晰度和正常饱和度。
- 远处照片通过缩放、透明度和对比度递减进入星河，不对照片文字使用强模糊。
- 最近的 2 至 4 张照片具有轻微边缘星尘和低强度轮廓光，帮助用户发现可点击对象。
- 非当前关注照片不添加大面积光晕。
- 图片加载失败时继续显示统一占位图、日期和标题。

## 6. 自由前进与后退

### 6.1 输入模型

滚轮和触控板输入都转换为对 `velocityZ` 的推动，而不是直接改变照片索引。

每一帧按以下顺序更新：

1. 将本帧滚轮增量加入速度。
2. 对速度设置最大值，限制普通鼠标一次滚动造成的冲刺。
3. 用速度更新连续相机位置。
4. 应用摩擦力，让相机自然减速。
5. 接近内容边界时额外增加阻力。
6. 速度低于停止阈值时归零，并停在当前位置。

### 6.2 停止行为

- 取消停止 150 毫秒后吸附最近照片的逻辑。
- 取消 `Math.round(cameraPosition)` 决定相机落点的逻辑。
- 用户可以停在任意世界坐标，包括两组照片之间。
- 页面仍计算“最近照片”，但只用于高亮、键盘操作、详情返回位置和辅助信息，不改变相机位置。
- 点击某张照片或时间节点时允许相机平滑前往该照片附近；该移动由用户明确触发。

### 6.3 速度手感

- 触控板的小增量直接保留，保证细腻移动。
- 鼠标滚轮的大增量经过曲线压缩，避免一次越过大量照片。
- 快速连续滚动可以叠加速度，但最大速度必须受限。
- 反向滚动优先抵消当前速度，随后再向反方向移动。
- 松手后惯性滑行建议控制在 250 至 700 毫秒内，具体时长由输入速度决定。
- 静止后不应有持续漂移。

### 6.4 辅助导航调整

- 删除“01 / 23”形式的分页计数。
- 顶部左右按钮改为“前往上一段记忆”和“前往下一段记忆”，只在点击时定位相邻照片。
- 底部时间轴保留，但改为连续进度轨道：当前位置指示器可以停在节点之间。
- 点击时间节点时平滑移动至对应照片；拖动时间轴游标时可以连续浏览整个星河。
- 键盘上/左、下/右仍前往相邻照片，`PageUp` 和 `PageDown` 可移动一个较大的固定纵深距离。
- 键盘移动完成后停在目标位置，不启动额外吸附。

## 7. 星河粒子系统

### 7.1 粒子分层

粒子至少分为三层，每层具有不同的空间速度和视觉职责。

| 层级 | 视觉 | 对移动的响应 |
| --- | --- | --- |
| 远景星点 | 小、暗、数量多，偶尔闪烁 | 缓慢视差，几乎不拉伸 |
| 中景星尘 | 柔和颗粒与少量薄雾团 | 明显沿前进方向移动 |
| 近景流星尘 | 数量少、亮度较高、快速掠过 | 速度越高，位移和短拖尾越明显 |

粒子不应平均铺满画面。中心通道适当稀疏，左右外围和照片之间可以更丰富，保证用户能看清行进方向和照片内容。

### 7.2 移动反馈

- 相机静止时：粒子缓慢漂浮，远景轻微闪烁，中景薄雾几乎不移动。
- 缓慢前进时：近景粒子向画面两侧和身后掠过，中景粒子产生轻微视差。
- 快速前进时：少量近景粒子形成短线状轨迹，纵深光带略微增强。
- 后退时：粒子方向反转，不能继续保持前进方向的拖动。
- 减速时：粒子拖尾随速度连续缩短，不突然切换状态。

粒子响应应读取相机真实速度，而不是读取“正在滚动”的布尔状态。

### 7.3 星河带

场景中央增加一条非常弱的纵深星河带，用稀疏粒子、薄雾和亮度梯度表示路线，不绘制实体地面或轨道。

- 星河带在远处更集中，在近处向左右散开。
- 星河带亮度低于照片标题和照片边缘。
- 滚动时星河带的纹理相位随相机位置移动，形成持续前进感。
- 不使用整屏大范围高斯模糊动画，以免性能下降。

### 7.4 技术实现建议

优先使用一个覆盖场景的 Canvas 粒子层，照片继续使用 DOM 和 CSS 3D：

- Canvas 负责星点、中近景粒子、速度拖线和光标拖尾。
- DOM 负责照片、标题、按钮、时间轴和详情层。
- 粒子层设置 `pointer-events: none`。
- 使用 `requestAnimationFrame` 驱动粒子和相机物理更新。
- 粒子对象使用固定对象池，避免每帧创建和销毁对象。
- 按设备像素比渲染，但内部像素比上限建议为 1.5，避免高分屏过载。
- 页面隐藏、切换到“MindPet 记得”或打开详情层时暂停高频粒子更新。

## 8. 星尘光标与拖尾

### 8.1 光标形态

回忆星河的空白移动区域隐藏系统箭头，使用自绘星尘光标：

- 核心是一颗 4 至 6 像素的暖白星点。
- 核心外有一圈低透明蓝金色微光，直径控制在 14 至 20 像素。
- 核心周围有 2 至 4 个不规则微粒，轻微旋转或闪动。
- 光标不使用箭头外形，不使用准星，不使用大圆环。
- 静止超过约 1.2 秒后降低亮度，但不能完全消失。

### 8.2 拖尾

拖尾由最近一段鼠标轨迹采样生成：

- 只保留约 160 至 260 毫秒的轨迹。
- 每个采样点释放 1 至 3 个微小粒子。
- 粒子沿光标反方向略微散开，逐渐缩小并降低透明度。
- 快速移动时拖尾更长但更稀疏，慢速移动时拖尾更短更柔和。
- 拖尾长度上限约为光标移动路径的 70 至 110 像素。
- 拖尾不能形成连续发光带，不能遮挡照片标题。

### 8.3 光标状态

| 区域或状态 | 光标行为 |
| --- | --- |
| 星河空白区域 | 星尘光标与短拖尾 |
| 照片卡片 | 系统 `pointer`，星尘拖尾快速淡出 |
| 顶部按钮与时间轴 | 系统 `pointer` |
| 详情层和分享弹窗 | 恢复系统默认光标 |
| “MindPet 记得” | 恢复系统默认光标，停止光标粒子更新 |
| 窗口失焦 | 隐藏星尘光标并清空拖尾 |

光标粒子层不能拦截点击。系统光标隐藏仅限星河场景空白区域，任何可操作控件必须继续显示标准交互光标。

## 9. 动效节奏

### 9.1 照片运动

- 照片世界位置保持稳定，不做持续上下浮动，避免用户滚动时难以判断位置。
- 只有距离相机最近的照片允许非常轻微的呼吸亮度变化，不改变其几何位置。
- 相机移动时，照片根据真实距离连续改变缩放、透明度和对比度。
- 照片进入近景的变化要平滑，不能在某个索引突然切换为“当前卡片”。

### 9.2 场景运动

- 星河背景的漂移速度低于照片世界的移动速度。
- 薄雾只做低频、低幅度变化。
- 速度增加时以粒子视差和轨迹长度作为主要反馈，不通过全屏缩放或晃动表达速度。
- 不加入镜头左右旋转、鼠标控制视角、自由飞行或横向位移。

## 10. 数据量与性能

### 10.1 渲染窗口

照片数量超过 60 条时，只挂载相机前后可见范围内的完整照片 DOM：

- 近区：完整图片、日期、标题，可点击。
- 中区：低分辨率缩略图或已缓存图片，减少阴影和滤镜。
- 远区：只保留轻量星点或几何占位，不加载原图。
- 离开渲染窗口的照片必须释放图片引用，但保留稳定布局坐标。

### 10.2 性能目标

- 普通桌面设备上移动时目标为 60 FPS，低配置设备最低保持可操作的 30 FPS。
- 单帧粒子与相机计算不进行数组深拷贝。
- Canvas 粒子建议从 180 至 320 个起步，根据窗口面积和性能档位调整。
- 近景高速粒子同时显示不超过约 36 个。
- 监听窗口尺寸变化时使用节流，不能每个 resize 事件都重建全部场景。

### 10.3 自适应降级

检测到连续掉帧时依次降低：

1. 近景粒子数量；
2. 中景薄雾分辨率；
3. 远景闪烁频率；
4. 光标拖尾粒子数量。

照片清晰度、滚轮控制和点击能力不能作为自动降级项。

## 11. 响应式规则

### 11.1 宽屏

- 左右照片可以同时出现，保持中心通道清晰。
- 同一记忆组最多显示 3 至 4 张可辨识照片。
- 时间轴完整显示节点和连续位置游标。

### 11.2 窄屏

- 减少同屏照片数量，同组优先使用左 1 右 1。
- 缩小左右距离和旋转角度，避免照片被窗口裁切。
- 标题保持最多两行，日期不可被遮挡。
- 时间轴隐藏次要日期文字，但保留连续游标与可点击节点。
- 星尘光标只用于具备精确指针的设备；触摸设备不创建光标拖尾。

## 12. 减少动态效果与可访问性

系统开启“减少动态效果”时：

- 相机仍可连续移动和停在任意位置。
- 禁用惯性滑行，滚轮输入直接以较低速度改变相机位置。
- 禁用近景速度拖线、星尘光标拖尾和薄雾动画。
- 保留少量静态星点与低速中景视差，维持空间关系。
- 点击时间节点的移动时间缩短到约 120 至 180 毫秒。

其他要求：

- 所有照片、相邻导航和时间节点保留清晰焦点样式。
- 键盘用户可以依次访问当前渲染窗口内的照片。
- 屏幕阅读器不读取远区占位节点。
- Canvas 只作为装饰层并标记为不可访问内容。
- 光标与拖尾不能成为唯一的操作提示。

## 13. 状态与边界

### 13.1 空状态

没有照片时不启动相机物理和高速粒子层。保留低速星空背景与“分享第一段回忆”入口。

### 13.2 加载状态

先显示星空和低速粒子，再渐入照片布局。不能先出现无定位照片后再整体跳动。

### 13.3 图片加载失败

照片位置保持不变，显示占位图、日期和标题。失败节点仍可打开详情。

### 13.4 详情层

打开详情时冻结相机速度，记录精确 `cameraZ`。关闭详情后恢复原来的精确位置，不移动到最近照片。

### 13.5 删除照片

删除照片后重新计算其所在记忆组，但保持相机世界位置。只有当相机位置落在新的内容边界外时，才用短距离平滑移动回有效范围。

### 13.6 新增照片

新照片加入星河起点附近。分享完成后可以明确导航到新照片，但用户之后仍可自由停留。

## 14. 实施结构建议

### 14.1 前端状态

建议拆分以下状态：

- `cameraZ`：连续相机位置；
- `cameraVelocityZ`：当前速度；
- `nearestMemoryId`：最近照片，仅用于语义和辅助导航；
- `layoutNodes`：所有照片的稳定世界坐标；
- `visibleNodeRange`：当前完整渲染范围；
- `pointerState`：光标位置、速度、是否位于可操作控件；
- `motionPreference`：系统动态效果偏好；
- `performanceTier`：粒子性能档位。

相机位置和速度应主要放在 `ref` 中由动画帧更新，避免每帧触发整页 React 重渲染。React 状态只同步较低频的最近照片、可见范围和导航信息。

### 14.2 组件拆分

建议将当前页面中的星河逻辑拆为：

- `MemoryCosmosViewport`：场景、输入与相机循环；
- `MemoryParticleCanvas`：星河粒子与速度反馈；
- `MemoryStardustCursor`：光标核心与拖尾；
- `MemoryCorridorWorld`：照片世界和虚拟化；
- `MemoryPhotoNode`：单张照片卡片；
- `MemoryDepthTimeline`：连续时间轴和节点导航。

详情层、分享弹窗和“MindPet 记得”保持独立，不并入相机动画循环。

### 14.3 实施顺序

1. 将相机从索引坐标改为连续世界坐标，移除自动吸附和分页计数。
2. 建立稳定照片布局生成器和碰撞检查，调整照片分组与纵深。
3. 实现相机速度、摩擦、反向输入和边界阻尼。
4. 实现照片虚拟化和连续距离视觉变化。
5. 增加三层 Canvas 星河粒子，并连接真实相机速度。
6. 增加星尘光标和拖尾，完成控件区域的系统光标切换。
7. 改造连续时间轴、键盘导航、详情返回和删除后的相机位置。
8. 完成响应式、减少动态效果和性能降级。

## 15. 本次不做

- 不加入背景音乐或粒子音效。

## 16. 验收标准

- 滚轮和触控板可以连续改变纵深位置，用户能停在任意两张照片之间。
- 停止输入后没有自动吸附、分页跳转或持续漂移。
- 页面不再出现“第 1 / 2 / 3 张”式分页体验。
- 照片比当前布局更靠近中心通道，组内更紧凑，同时远处能看到更长的照片序列。
- 左右照片始终朝向用户，近景照片之间没有明显遮挡。
- 前进和后退时，近、中、远三层粒子的方向和速度均与相机运动一致。
- 静止时粒子保持低速星空感，移动时能明确感受到穿行，但照片仍然清晰。
- 星尘光标在星河空白区域显示短拖尾，进入照片、按钮、详情层和“MindPet 记得”后恢复正确的系统光标。
- 打开并关闭详情后回到原来的精确纵深位置。
- 超过 60 张照片时，远处照片不会全部加载为完整 DOM 和原图。
- 开启减少动态效果后，仍能自由前后移动，且惯性、速度拖线和光标拖尾被关闭。
- 明暗主题、普通鼠标、触控板、键盘、窄屏、图片失败和大量照片场景均保持可操作。

## 17. 方案假设

- “不要限制在 1、2、3 页”理解为取消按照片索引分页和停止吸附，而不是取消最早、最新记忆的数据边界。
- 用户依然通过滚轮或触控板控制前后移动，不增加按住鼠标拖拽场景。
- 星尘拖尾只存在于回忆星河的空白区域，不覆盖全应用光标。
- 星河粒子和光标拖尾使用程序生成，不新增外部图片或视频素材。
