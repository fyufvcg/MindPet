# 会话上下文管理

上下文模块服务于当前会话和任务，独立于长期记忆。Spring AI 1.1.8 的 `ToolCallAdvisor` 继续拥有模型与工具循环；本模块通过其逐轮钩子组装输入，不实现另一套 Agent 循环。

## 数据边界

- `agent_context_message`：完整会话文本，使用与后端会话记录一致的消息 ID，幂等保存。当前输入在执行前归档，助手回复及失败、停止状态在执行结束时归档。
- `agent_context_image`：用户提交的图片，可由历史回读工具显式重新装载。界面截图属于短期环境观察，后续新观察替代旧图。
- `agent_context_checkpoint`：带覆盖位置的结构化历史检查点，保留版本；编辑已覆盖记录时使旧覆盖失效。
- `agent_context_import`：已有会话记录的导入版本；只处理新增或变动的记录，当前输入前先导入旧记录，避免顺序反转。
- `agent_context_contract`：用户原文约束、稳定 id 和来源 sequence；独立于有损摘要，支持修正或撤销。来源被编辑后，失效引用自动清除。
- `agent_context_trace`：每轮输入估算、工具定义、系统与记忆提示、Skill、工具结果、图片预留，以及任务用量。
- 原有 `agent_task`、`agent_tool_output`：执行状态、计划、完整工具输出和压缩前的轮次记录。

这些表不写入记忆事实、向量、知识图谱或馆长状态。原有记忆写入、检索、整理、遗忘算法不变。读取原有 `session_messages` 仅用于导入已有会话；该表原来的保留策略不变。已经被旧策略删除的历史无法凭空恢复。

## 历史与压缩

桌面主聊天、快捷窗口和桌宠只发送当前输入。后端读取归档与最新检查点，不再使用用户配置的 N 轮作为上下文窗口。读取历史阶段只查询数据库，不调用摘要模型。历史按 sequence 倒序分页装载，最多约两倍输入预算；更早的未装载区间会明确标注，完整原文仍能搜索。系统规则、工具定义、Skill、当前问题和附件全部组装后，统一判断容量压力；每次工具执行后的下一轮也执行检查。

压缩在容量压力下触发，不按每 N 条消息调用模型。检查点必须包含 goal、constraints、decisions、completed、evidence、pending、failures、artifacts；使用无工具的 Spring AI 后台客户端生成，有限时和输出上限。原始记录不因压缩而删除。摘要超时、格式错误或摘要预算不足时，使用明确标注为不完整的原文摘录和回读入口；不将失败摘要标成已覆盖的检查点。当前请求、附件、固定约束和最近完整工具交换受保护，保护内容本身无法装入时返回具体限制。连续历史前缀的有效摘要才推进持久检查点；条件写入与清空版本避免迟到的摘要覆盖用户编辑或重新写回已清空内容。

工具调用和对应响应作为完整块保留。最近仍需使用的结果不会仅因出现第三条工具消息而被裁剪。大结果首先归档，返回有效 JSON，包括状态、头尾片段、task_id/call_id 和回读入口。分页工具按实际返回的 nextOffset 继续，而非假设请求长度已全部返回。

`agent_read_history(query,after_sequence,limit,offset,include_images)` 回读本会话原文；include_images 显式装载第一条匹配记录的用户图片。`agent_read_output(task_id,call_id,offset,length)` 可读取当前或同一用户同一会话的旧任务输出。

## 能力生命周期

Desktop 和 Java 基础工具保持常驻。外部 MCP 展开的工具定义同时受总预算限制，过大定义不会挤掉常驻能力，未装入的定义可继续按需发现。Skill 简介目录沿用既有发现方式；正文在统一 Token 预算内公平分配，`agent_load_skill(pin=true)` 可保护当前步骤依赖的 Skill 引用，多个固定引用也公平分配；超出部分明确给出资源分页入口，整个 Skill 正文区域也有总上限。

模型在阶段结束时调用 `agent_release_capabilities` 释放已用完的 Skill 正文或已展开的外部 MCP 定义。这个操作不卸载 Skill、不取消用户的 MCP 选择，也不断开 MCP。后续可重新发现、加载。`agent_update_plan` 可携带 `active_skill_ids`、`active_tool_names` 声明新阶段的依赖，系统在更新计划时同时回收其余正文或外部定义；省略时保留现状。Desktop 和 Java 基础工具不受该操作影响。系统不根据几轮未使用就自动删除仍有依赖的 Skill。

## 配置

旧 `agent.context-max-chars` 已退出运行策略。可通过 Spring 配置或对应环境变量设置：

```yaml
agent:
  context:
    window-tokens: 65536
    max-input-tokens: 32000
    output-reserve-tokens: 8192
    safety-tokens: 2048
    # 精确模型名匹配，分号分隔；自定义供应商的容量由部署者核对。
    model-windows: "model-a=32768;model-b=131072"
    task-soft-tokens: 120000
    task-max-tokens: 400000
```

有效输入预算为 `min(max-input-tokens, window-tokens-output-reserve-tokens-safety-tokens)`。固定内容或最新完整交互无法放入预算时明确报错，保留原始数据，不发送超限请求。单次整理最多处理约三倍输入预算、最多 8 段并受总共 60 秒限制；达到限制时使用带回读入口的摘录，不继续无界调用摘要模型。模型容量不能通过本地估算自动证明。

任务软预算会提示模型优先利用已有证据、完成目标；主模型调用前检查本次输入及最大输出预留，摘要每一段也检查输入与输出额度，并保留主模型的可用额度。摘要调用串行结算后再判断下一段；失败且缺少 usage 的摘要按预估输入加最大输出保守计入，并标为估算。实际已产生的调用仍计入统计。不能承诺精确的货币上限。恢复任务保留历次用量，当前恢复请求获得新的执行预算，避免将历史用量再次作为本次账单累计。

## 用量展示

本地估算使用独立的 o200k_base tokenizer。它不是所有供应商的实际 tokenizer。工具 Schema 也计入输入；图片目前每张预留 4096 Token，需为实际服务保留安全余量。

`context_usage` 把后端最近组装的上下文占用传回界面，前端不再用固定提示词基数和消息轮数推测。它与整个任务累计用量分开显示；达到估算容量不再直接禁用输入和附件。

模型返回 usage 时采用其计数；输入或输出计数单侧缺失时仅估算缺失部分，并标注 estimated。运行期上下文摘要的用量计入任务；失败和取消时也发送已有用量。日志中包含估算的记录显示 `≈`。长期记忆后台处理保留原有链路，本模块不改变其算法或调度。

原有前端记忆摘要批次从旧轮数配置迁移为 `memorySummaryBatchRounds`，保留原有值与默认值。它只控制既有记忆归档批次，不控制模型上下文，也不使用新的运行检查点替代原有记忆摘要或修改 isSummarized。

## 部署与检查

启动时自动建立上述独立 SQLite 表，无需清理或迁移记忆表。清空当前/全部会话通过后端确认后再更新界面，清除会话消息、运行上下文、计划和输出，保留会话列表与长期记忆；删除会话额外移除会话元信息。正在准备或执行任务的会话返回 409，待停止退出后重试；后台记忆摘要不占用会话执行锁。任务持久化有会话版本保护，取消后迟到的工具结果不能复活已清空的会话。

2026-10-16 验证：40 项 Java 回归与 10 项本地工具工作流检查通过，Electron 构建及类型检查通过。Java 回归使用脚本化 Spring AI 模型、MockMvc 与临时 SQLite，覆盖预算压力、摘要异常、历史检查点、任务取消与恢复、工具结果配对、Skill 阶段依赖、计数缺失、清空一致性和记忆边界；另执行 Electron 构建/类型检查及本地工具工作流回归。未调用真实模型，也未操作用户桌面。

## 查询结果复用

同一任务内，内置 `web_search` 在一分钟内对相同查询及选项复用成功证据，返回简要内容和原工具输出引用；失败结果不缓存。此逻辑不应用于用户配置的 MCP，也不用于会随操作变化的本地文件或桌面观察。`web_fetch` 继续使用已有页面缓存，搜索摘要足够时无需抓取页面。语义相近但内容不同的查询仍由模型结合证据判断，系统不新增前置分类模型。
