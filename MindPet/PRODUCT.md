# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是希望获得持续 AI 陪伴，并希望通过聊天快速操作微信、QQ 和本地电脑的个人用户。

## Product Purpose

MindPet 通过桌面宠物形态提供聊天陪伴、情感互动、记忆能力和可扩展的 MCP 服务。用户可以通过对话获得所需服务，包括生成文件和执行本地电脑操作。成功意味着用户能在自然聊天中获得持续陪伴，并便捷完成原本需要多个工具的任务。

## Positioning

产品将桌面宠物、长期记忆、情感功能和自定义 MCP 服务结合在一个聊天入口中，定位更接近 OpenClaw，而不是单纯的 AI 聊天窗口。

## Operating Context

产品以 Electron 桌面应用运行，用户主要通过桌面宠物和聊天界面使用服务。典型工作流包括聊天陪伴、调用 MCP 服务、连接微信或 QQ、操作本地电脑，以及生成和处理文件。

## Capabilities and Constraints

- 当前后端地址必须保持不变。
- 支持的模型需要能够软切换。
- 现有桌面端定位可以适当调整，尚未固定为不可改变的产品方向。
- 自定义 MCP 服务是核心扩展机制，需支持本地电脑操作和文件生成等能力。
- API key 等敏感配置保存在本地。
- 用户信息及相关数据默认本地存储。
- 当前未确认需要额外的权限或特定权限审批流程。
- 具体品牌名、素材和视觉身份可以调整。

## Brand Commitments

当前工作名称为 MindPet，但品牌名、品牌素材和视觉身份均未被确认必须保留。

## Evidence on Hand

- 现有 Electron 应用代码位于 `src`。
- 现有聊天、桌宠、记忆、MCP/RPA、文件和模型相关实现位于 `src/main`、`src/preload` 和 `src/renderer/src`。
- 当前仓库没有确认的外部案例、用户数据、评价或宣传材料；后续工作不得自行编造这些证据。

## Product Principles

- 陪伴体验应与实际任务完成能力结合。
- 聊天应成为调用服务和操作工具的主要入口。
- 记忆与情感互动应服务于连续、个性化的使用体验。
- MCP 扩展能力应覆盖真实的本地工作流，而不局限于问答。
- 用户数据和敏感配置应保持本地优先。

## Accessibility & Inclusion

目前尚未确认产品特定的无障碍标准或用户辅助需求。
